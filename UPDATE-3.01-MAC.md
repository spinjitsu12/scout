# Update SCOUT 3.01 with Finder and GitHub Desktop

This download is the development source for version **3.0.1**, displayed as 3.01. GitHub builds the playable Windows and Apple silicon apps from it. Keep the existing public `spinjitsu12/scout` repository.

1. **Locate your existing clone.** Open GitHub Desktop, select **scout**, and choose **Repository → Show in Finder**. This opens the local folder containing `package.json`, `src`, `public` and `electron`. Leave this window open.
2. **Preserve current work.** Review **Changes** in GitHub Desktop. Commit any existing edits you want to keep before applying the checkpoint. Switch **Current Branch** to `main`, click **Fetch origin**, and **Pull origin** if offered. Then use **Branch → New Branch** to create `update-3.01` from `main`. A Finder copy of the current source outside the repository provides another backup.
3. **Extract the checkpoint.** Download `SCOUT-3.0.1-Development-Checkpoint.zip`, double-click it in Finder, then open the extracted **SCOUT** folder in a second window. The ZIP must stay outside the cloned repository.
4. **Apply the source inside the clone.** Copy the contents of the extracted SCOUT folder into the existing clone. Copy loose files such as `package.json` and `package-lock.json` to the matching destination, choosing **Replace** for those supplied files. For project folders, merge their contents into the matching folder. If Finder offers only **Stop** or **Replace** for an entire folder, choose **Stop**, open both corresponding folders and copy their contents, repeating for nested folders. This keeps any extra local files. Include `src`, `public`, `electron`, `scripts`, `build`, `tests`, `qa`, configuration files and documentation. Keep the clone's root and `.git` intact; player saves, credentials and `node_modules` stay where they are. Do not create an extra SCOUT folder inside the clone.
5. **Install the combined workflow locally.** Press **Command + Shift + Period** in Finder to show hidden items. In both source windows open **.github → workflows**. Copy `desktop-release.yml` from the extracted checkpoint into the clone's matching folder, replacing that one file if present. If the clone still has `windows-release.yml`, move only that old file to your backup folder outside the repository. Preserve unrelated workflows. The new workflow is already in this ZIP; you do not need a separate YAML download or GitHub's code editor.
6. **Review and save the update.** Return to GitHub Desktop. Confirm that both package files show `3.0.1`, that `desktop-release.yml` is added/updated and the old `windows-release.yml` is removed. Desktop may show the workflow change as a rename. Check the changed source files against any custom edits you kept. Enter **SCOUT 3.01 physics and smoothness polish** in **Summary**, then click **Commit to update-3.01** and **Publish branch** or **Push origin**.
7. **Validate on the new commit.** The combined workflow must exist on `main` to appear in Actions. When ready to run its platform checks, switch **Current Branch** to `main`, use **Current Branch → Choose a branch to merge into main**, select `update-3.01`, merge, and click **Push origin**. Open [the repository's Actions page](https://github.com/spinjitsu12/scout/actions), choose **Build Windows and Mac game → Run workflow**, select `main`, and leave **Publish this version to the public update channel** unchecked. Start a fresh run; rerunning an old failure tests its old commit.
8. **Wait for both platforms.** The `build` job is Windows x64; **Build Apple silicon Mac app** is Mac ARM64. Both need green checks. The Mac job must pass app verification, archive verification and the native Metal smoke. If a job fails, retain its error log and Mac QA artifact; do not publish that run.
9. **Try the packaged game.** At the bottom of the successful run, download `SCOUT-Mac-Apple-Silicon-3.0.1`. Double-click the artifact ZIP, then the inner `SCOUT-3.0.1-macOS-Apple-Silicon.zip`. Drag `SCOUT.app` into **Applications**, replacing the previous app after quitting it. You can also install from the included DMG. `README-MAC.md` describes first-launch approval. Test the three careers, driving, walking, sound, fullscreen and save/quit. The Windows artifact is `SCOUT-Windows-3.0.1`; its portable EXE requires Windows.
10. **Publish after validation.** Once both platform checks and target-device playtests pass, run the same workflow again with **Publish this version to the public update channel** enabled. It publishes both platforms under `v3.0.1`. Only publish a version once; later releases need a new package version.

You can upload checked source for the non-publishing build without making it a public game update. The workflow publishes only for its explicit publishing option or a matching version tag. Do not create a version tag during validation.

Current evidence and native release gates are in `QA-3.01.md`. For continued development, open this same cloned folder in Codex and ask it to read `AGENTS.md` and `CODEX-HANDOFF.md`, preserve your changes, run the remaining native checks and save Git checkpoints. You do not need to type Terminal commands.
