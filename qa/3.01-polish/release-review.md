# SCOUT 3.0.1 release review — 4 October 2026

This is a read-only review of release code and configuration. No native packaging, remote Git operation or publication was performed here; root generated current support code during the coordinated build. The coordinated main QA pass completed 29 gameplay suites, 103 desktop tests, the final production build, 45 four-process native Linux checks and six synchronized art checks. Native Mac and Windows results must be recorded separately.

## Result and remaining gates

No blocking packaging defect was found in the reviewed source or final production output. This does **not** certify a native release or guarantee that the game has no errors. After the coordinated build completed successfully, this reviewer checked the actual new JS bundle, HTML, public asset bytes, engine notice and generated native save engine; that output review passed. Native package and hardware gates remain below.

The following checks still matter before publishing a release:

1. Run the combined workflow for the new commit with **Publish this version to the public update channel** unchecked. Both platform jobs must pass. The historical Mac run failed under the former software Vulkan configuration; the Metal correction has not been proved by this Linux review.
2. Confirm the fresh Apple silicon app passes native signature verification, delivered ZIP verification, and the real Metal smoke test. Linux smoke-harness unit tests cannot replace that result.
3. Open the delivered DMG on an Apple silicon Mac, install its app through Finder, and launch that installed app. CI builds and uploads the DMG, but the current verifiers inspect the unpacked app and ZIP, not a mounted DMG.
4. Playtest pointer capture, window/fullscreen transitions, audio, long drives, pause/resume, memory and frame time on real hardware. The Mac smoke test verifies startup, save slots, display transitions, offline updates and visible scene pixels; it does not establish those broader gameplay or hardware results.
5. Launch the fresh Windows portable EXE on Windows. The Windows job verifies packaging, executable identity/hash and bundled bytes, but does not launch its packaged UI. Its desktop unit tests and a rendered Linux fixture do not prove Windows graphics, input or audio behavior.

- The Mac job uses `macos-15` and builds ARM64 ZIP and DMG. The configuration has no Intel/universal target. GitHub's current primary runner documentation lists `macos-15` as Apple silicon ARM64 for public repositories. The archive verifier additionally rejects other native binary architectures.

GitHub's own runner release workflow uses `download-artifact@v8`; its repository README could not be retrieved in this review, so it is not claimed as independently read here.

It creates a release rather than replacing an existing release; publishing a version already released will fail and requires a new version.

## Bundled engine, offline behavior and native bridges

- Cannon ES is a production dependency pinned to `0.20.0` with the expected lockfile integrity and MIT license. `public/licenses/cannon-es-MIT.txt` is byte-for-byte identical to the installed package's `LICENSE`; `CREDITS-ENGINE.md` identifies the engine and upstream.
- The playable `ImmersiveWorld.tsx` imports `immersive-physics.ts`, which imports Cannon from the local dependency. No CDN, engine download, WebAssembly loader or eval-based script path is used by that integration. Vite's relative base, `public` asset copying and the `dist/**` packaging inclusion provide the offline production path. The fresh built output was checked as detailed below; native payload verification remains pending.
- `index.html` permits local scripts, assets and connections through its CSP, with no remote script or eval permission. The native main process blocks renderer HTTP, HTTPS and WebSocket requests. Native update checks run outside that renderer request path and are started after the window is shown, so a network failure does not hold up career loading.
- Both native verifier lists include `exit-checkpoint.cjs` and `game-permissions.cjs`, and byte-compare those helpers along with the current main/preload/save/update modules. Both compare every current `dist` file recursively, including bundled license notices.
- Save slots capture their slot identity, serialize atomic writes and preserve an earlier valid career. Close requests flush the live renderer state, await all preload close listeners, then flush native writes. Repeated close requests share one checkpoint. Failed writes retain the app and offer an explicit player choice. Generated `electron/game-engine.cjs` must be refreshed from the current `game.ts`; the existing npm pretest/build scripts do that in the coordinated pass.
- Mouse capture is allowed only for `pointerLock` from the trusted bundled main frame and active main window. The installed Electron type definitions expose the `requestingUrl` and `isMainFrame` fields used by those handlers. Other permissions remain denied. Actual Mac/Windows pointer behavior remains a playtest gate.
- The Mac smoke harness copies the packaged app into a temporary directory, re-signs only that test copy, and wraps the **real original packaged main, preload, save engine and UI**. It uses an isolated profile and replaces update network transport solely to test offline behavior. It does not substitute a dummy game renderer. Its requestAnimationFrame pixel probe reads the real WebGL2 canvas, records renderer/vendor/version, rejects blank/lost contexts and GL errors, and requires distinct visible scene colors.
- The smoke arguments are `--use-angle=metal`; the previous forced Vulkan/SwiftShader arguments are absent. Renderer load/preload/process errors, GPU crashes and error-level console messages fail the smoke. Its modern single-details-object console listener matches Electron `44.5.1`'s declared event shape. Native execution is explicitly rejected outside Darwin ARM64.
- JavaScript syntax checks passed for main, preload, game permissions and the Windows, Mac app, Mac ZIP and Mac smoke verification scripts. This is syntax validation, not a native run.

## Diagnostics and evidence limits

Mac smoke stage JSON, GPU/page diagnostics and screenshot are kept in `qa-mac/`; an `always()` artifact upload retains them for **14 days** when files exist. Windows/Mac package artifacts are retained for **30 days**. Process stdout/stderr remain in the GitHub job log; the workflow does not upload a separate raw log file. A launch failure before the harness writes its report can therefore leave only the job log, and `if-no-files-found: ignore` does not manufacture diagnostics. Retain the failed run's log as well as any QA artifact when investigating native startup failures.

The Mac ZIP verifier CRC-checks every entry, validates paths and modes, preserves framework links, checks ARM64 native binaries, and on macOS extracts with `ditto` and invokes the full native app verifier including `codesign`. The Mac app is ad-hoc signed (`identity: '-'`) and not notarized; successful signature verification would not remove first-launch Gatekeeper approval for a downloaded app.
